# 🌐 MarkForge Internationalization (i18n) Architecture

MarkForge incorporates a type-safe, multi-language internationalization framework designed for zero-overhead client rendering and seamless localized developer experiences.

---

## 1. Supported Locales

| Locale Code | Language | Default | Coverage |
|---|---|---|---|
| `id` | Bahasa Indonesia | Yes | 100% (Studio, Audit, Modals, Starters) |
| `en` | English | Alternative | 100% (Studio, Audit, Modals, Starters) |

---

## 2. Directory Structure

All localization resources reside in `packages/web/lib/i18n/`:

```
packages/web/lib/i18n/
├── dictionaries/
│   ├── id.ts               # Indonesian translations dictionary
│   ├── en.ts               # English translations dictionary
│   └── index.ts            # Dictionary aggregator & symmetry validation
├── context.tsx             # React Context Provider (`I18nProvider`, `useI18n`)
├── types.ts                # TypeScript types & recursive key path generator
└── index.ts                # Public package barrel exports
```

---

## 3. Type-Safe Key Resolution

MarkForge enforces strict compile-time key checking through recursive TypeScript mapped types:

```typescript
// Translating with parameter interpolation
const { t, locale, setLocale } = useI18n();

// Resolved key with type-hinting:
const wordCountText = t('editor.wordsCount', { count: 350 });
// Output (id): "350 kata"
// Output (en): "350 words"
```

### 3.1. Fallback Strategy
If a key is omitted in the target dictionary:
1. Falls back automatically to the corresponding English (`en`) translation.
2. If absent in both dictionaries, gracefully renders the raw dot-notated key path (e.g., `'header.newKey'`) rather than throwing runtime errors.

---

## 4. LocalStorage Persistence

The user's preferred language is persisted in `localStorage` under the key `markforge_locale`. When a user changes languages:
1. `setLocale('en')` updates the React state instantaneously.
2. Changes are written to `localStorage`.
3. Subsequent page reloads automatically restore the saved locale.

---

## 5. Adding a New Language

To contribute a new language (e.g., Spanish `es`):
1. Create `packages/web/lib/i18n/dictionaries/es.ts` matching the `LocaleDictionary` interface.
2. Register the locale in `packages/web/lib/i18n/types.ts`:
   ```typescript
   export type Locale = 'id' | 'en' | 'es';
   ```
3. Export the dictionary in `packages/web/lib/i18n/dictionaries/index.ts`.
4. Run `bun test packages/web/test/i18n.test.ts` to verify 100% key symmetry across all dictionaries.
